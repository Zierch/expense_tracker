# v1.7.0 — a ceiling per category, and rows that come back every month

Two things the app could not do before: it could not tell you how much of a
category's spending you had used up, and it could not remember a transaction you
pay every month.

## Budgets

The Expense tab of *Statistics* now measures each category against a ceiling you
set. Tap a row to type a monthly amount — the row grows a bar that stays green
while there is room, turns amber in the last fifth, and goes red once it is
passed, with what is left (or how far over) next to the amount. Tap again to
change it, or press *Remove* to drop it. A category with a ceiling but no spending
this month still shows, at zero spent, so it can always be reached again.

Ceilings are monthly and per category, in the sense the breakdown already uses:
the subcategory where there is one, the category otherwise. They are not tied to
a particular month's figures — one amount per category, compared against whatever
that month's spending turns out to be.

## Recurring transactions

The add screen has a *Repeat monthly* switch. Turn it on and the transaction you
save also becomes a template: on that day of each month, a new row is added for
you. It is written once, the first time the app is opened that month, and never
for a month that has already gone by — so nothing silently appears in your history
for the weeks the phone was in a drawer.

The repeat icon on the dashboard opens the list. Switch a template off to pause it
without losing the history, or swipe it to delete it — the transactions it already
made stay. Days are held between the 1st and the 28th so that February has the day
too. A template is created from a transaction, not from its own form: one screen
decides what a transaction is, and adding a second one would be two places to keep
in step.

## Upgrading

The database went from version 2 to 4 across these two features. Both steps only
add a table, so an existing install keeps every transaction, every category and —
from 3 onwards — every budget. Nothing is rewritten and nothing is migrated by
hand.

**Installing.** Download the APK attached here, or use *Backup* → *Check for
updates*. If an older debug-signed build of this app is installed, uninstall it
first: Android refuses to update across a different signing key, and uninstalling
deletes the local database. The app is not on Google Play.

**Verifying what you downloaded.** The build details below carry this APK's
SHA-256, and the signing certificate is public: SHA-1
`b2f50e9c44f5724b9e17b57bd7b6a3e624f42cae` (the Console shows it colon-separated
as `B2:F5:0E:9C:44:F5:72:4B:9E:17:B5:7B:D7:B6:A3:E6:24:F4:2C:AE`). The README
section *Verifying a download*
(https://github.com/Zierch/expense_tracker#verifying-a-download) has the two
commands. Install from this page only: a copy forwarded through a chat app cannot
be checked against anything.

**Google Drive backup.** Sign-in runs on an OAuth consent screen that is still in
*Testing*, so only accounts on the test-user list can use it. Ask the maintainer
to add the Google address you want to export from, then use *Backup* → *Sign in
with Google* → *Export*. The JSON file is written to
`My Drive/Expense Tracker/expense-tracker-<YYYY-MM>.json` **in your own Drive**;
re-exporting the same month replaces that file. Nothing is uploaded anywhere
except when you press Export, and the app only requests the `drive.file` scope, so
it can only see the files it created itself.

**Privacy.** No analytics, no ads, no accounts, no server of ours. The update
check contacts GitHub's public release API and carries no account or personal
data — your IP address and a User-Agent string, as with any page load; details in
`PRIVACY.md`. Android Auto Backup and device-to-device transfer are disabled,
which means the phone's copy is the only copy unless you export it.
