# v1.9.0 — every month, and a spreadsheet

Two gaps in export closed, and one in what the app said about itself.

**One button for every month.** *Backup* → *Export every month to Drive* walks
every month that has a transaction in it and writes one JSON file per month, the
same file the month-by-month button writes. The button says which month it is on
while it runs, and the summary at the end says how many files were written. A
month you already exported is replaced, not duplicated, so running it again costs
only time — and a failure halfway says how far it got, with the months already
uploaded left in place.

**CSV for a spreadsheet.** The report card now offers *Save CSV* beside *Export
PDF*, for the same date range: one row per transaction, oldest first, with the
date, type, category, subcategory, amount and note. Android's own *Save as* dialog
picks where it goes — Downloads, a folder of yours, a cloud drive — so there is no
storage permission to grant and no Google account involved.

Nothing in the file is left to the spreadsheet to guess: fields that hold a comma,
a quote or a line break are quoted the way RFC 4180 says, amounts stay numbers
instead of turning into text, and a note that begins with `=`, `+`, `-` or `@` gets
a leading `'` — a backup file can carry text this app never typed, and a CSV that
ran what a stranger wrote would be worse than useless.

**What it will not do.** The CSV is transactions only: no totals, no chart, no
layout. That is what the PDF is for. A month with nothing in it is not exported at
all, because an empty file only makes the folder harder to read.

**Under the hood.** Every date-range query — the dashboard's month, both
statistics tabs, the exports, and the duplicate check an import runs once per row —
now reads through an index on `transactions.date`. The database upgrades itself on
first open (schema 5 → 6); no action from you, and no rows are touched.

**Installing.** Download the APK attached here, or use *Backup* → *Check for
updates*. If an older debug-signed build of this app is installed, uninstall it
first: Android refuses to update across a different signing key, and uninstalling
deletes the local database. The app is not on Google Play.

**Verifying what you downloaded.** The build details below carry this APK's
SHA-256, and the signing certificate is public: SHA-1
`b2f50e9c44f5724b9e17b57bd7b6a3e624f42cae` (the Console shows it colon-separated
as `B2:F5:0E:9C:44:F5:72:4B:9E:17:B5:7B:D7:B6:A3:E6:24:F4:2C:AE`). The README
section *Verifying a download*
(https://github.com/Zierch/expense_tracker#verifying-a-download) has the two
commands. Install from this page only: a copy forwarded through a chat app cannot
be checked against anything.

**Google Drive backup.** Sign-in runs on an OAuth consent screen that is still in
*Testing*, so only accounts on the test-user list can use it. Ask the maintainer
to add the Google address you want to export from, then use *Backup* → *Sign in
with Google* → *Export*. The JSON file is written to
`My Drive/Expense Tracker/expense-tracker-<YYYY-MM>.json` **in your own Drive**;
re-exporting the same month replaces that file. Nothing is uploaded anywhere
except when you press Export, and the app only requests the `drive.file` scope, so
it can only see the files it created itself.

**Privacy.** No analytics, no ads, no accounts, no server of ours. The update
check contacts GitHub's public release API and carries no account or personal
data — your IP address and a User-Agent string, as with any page load; details in
`PRIVACY.md`. Android Auto Backup and device-to-device transfer are disabled,
which means the phone's copy is the only copy unless you export it.
