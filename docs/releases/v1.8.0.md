# v1.8.0 — put your backups back

The app could archive a month to Google Drive, but it could not read one back.
That was the wrong half to have: a backup is only worth having if the day the
phone is lost, wiped, or replaced by a new one is not the day the history ends.
So this release adds the way back.

**Import a file.** *Backup* → *Import a backup* → *Choose a backup file* opens
Android's own file chooser; pick one of the `expense-tracker-<YYYY-MM>.json` files
this app exported (from Downloads, or wherever you saved it) and its transactions
are written back. No Google account needed for this half.

**Restore from Google Drive.** Signed in, the same card offers *Restore from
Google Drive*: it lists the months already archived in your `Expense Tracker`
folder, all of them chosen to begin with, and imports the ones you keep ticked.
Progress says which month it is on, and the summary at the end says how many
transactions arrived and how many files could not be read.

**Nothing is imported twice.** A transaction is matched on what you can see —
its day, type, amount, category, subcategory and note — rather than on the id the
backup recorded, because those ids mean nothing in a database that numbers its
rows from one. Importing the same file again therefore writes nothing, and a
restore that failed halfway can simply be run again.

Two coffees on the same day for the same amount are two transactions, not a
duplicate: the note is part of what identifies a row, and one `Coffee` with a
friend next to it is enough to tell them apart.

**What it brings with it.** A backup can name a category or subcategory this
install has never seen — its own custom ones, or the ones it seeded differently.
Those are created rather than renamed or dropped, matched on the name exactly, so
what you restore is what you had.

**What it will not do.** It does not replace or clear anything: a month you
import is added beside whatever is already stored, never on top of it. There is
no "delete the month first" switch, and no import from another app's format — the
file has to be one this app wrote. A file from a newer version of the app is
refused with a sentence saying so, rather than half-read.

Nothing else changes.

**Installing.** Download the APK attached here, or use *Backup* → *Check for
updates*. If an older debug-signed build of this app is installed, uninstall it
first: Android refuses to update across a different signing key, and uninstalling
deletes the local database. The app is not on Google Play.

**Verifying what you downloaded.** The build details below carry this APK's
SHA-256, and the signing certificate is public: SHA-1
`b2f50e9c44f5724b9e17b57bd7b6a3e624f42cae` (the Console shows it colon-separated
as `B2:F5:0E:9C:44:F5:72:4B:9E:17:B5:7B:D7:B6:A3:E6:24:F4:2C:AE`). The README
section *Verifying a download*
(https://github.com/Zierch/expense_tracker#verifying-a-download) has the two
commands. Install from this page only: a copy forwarded through a chat app cannot
be checked against anything.

**Google Drive backup.** Sign-in runs on an OAuth consent screen that is still in
*Testing*, so only accounts on the test-user list can use it. Ask the maintainer
to add the Google address you want to export from, then use *Backup* → *Sign in
with Google* → *Export*. The JSON file is written to
`My Drive/Expense Tracker/expense-tracker-<YYYY-MM>.json` **in your own Drive**;
re-exporting the same month replaces that file. Nothing is uploaded anywhere
except when you press Export, and the app only requests the `drive.file` scope, so
it can only see the files it created itself.

**Privacy.** No analytics, no ads, no accounts, no server of ours. The update
check contacts GitHub's public release API and carries no account or personal
data — your IP address and a User-Agent string, as with any page load; details in
`PRIVACY.md`. Android Auto Backup and device-to-device transfer are disabled,
which means the phone's copy is the only copy unless you export it.
